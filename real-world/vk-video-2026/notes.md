## 1. ПРАВИЛА ПРОГРАММЫ

### Обязательно
- 10 req/s — не превышать.
- Только свои аккаунты (у нас 2 аккаунта).
- Обязательный скриншот/видео + curl/HTTP запрос в отчёте.
- Отчёт должен быть кратким, с ручной проверкой (без ИИ и сканеров).

### RCE / SQLi / LFI / SSTI-политика
- Разрешено использовать ТОЛЬКО минимальный PoC (sleep, чтение /etc/passwd, hostname).
- Выход за рамки PoC — ТОЛЬКО после письменного разрешения от VK.

### Что НЕ принимается (частые ошибки новичков)
- CSRF на logout.
- Open Redirect без кражи токена.
- Отсутствие CSRF-токена без доказанного impact.
- SSRF без доступа к внутренним ресурсам VK (Blind SSRF).
- Отсутствие заголовков безопасности (CSP, HSTS и т.д.).
- Self-XSS, Clickjacking, Tabnabbing.
- DOS, спам, флуд.
- Раскрытие версий ПО, публичных IP/hostname, sourcemap.
- Отчёты, сгенерированные ИИ (нужен ручной PoC).

### Критичность и выплаты (Tier1)
- **RCE:** 1 000 000 ₽

## 5. ВЕКТОРА В РАБОТЕ

### Приоритет 1: IDOR (Tier1)
- [ ] `GET /api/v1/video/{video_id}` — чужое видео
- [ ] `GET /api/v1/user/{user_id}/videos` — чужие видео
- [ ] `POST /api/v1/video/{video_id}/edit` — доступ к чужому видео
- [ ] `GET /api/v1/playlist/{playlist_id}` — чужой плейлист

### Приоритет 2: Race Condition (Гонка)
- [ ] Авторизация (несколько запросов в одну миллисекунду).
- [ ] Регистрация (2 запроса на 1 телефон/email).
- [ ] Накрутка лайков/просмотров (параллельные запросы).

### Приоритет 3: Broken Access Control
- [ ] Доступ к чужой аналитике канала.
- [ ] Доступ к скрытым видео (private/unlisted).
- [ ] Доступ к админке (если есть).

### Приоритет 4: Business Logic
- [ ] Обход лимитов на загрузку.
- [ ] Бесплатный доступ к платному контенту.
- [ ] Нагрузка на сервис.

## 6. ГИПОТЕЗЫ (Что вероятнее найти)

1. **IDOR в API (самое вероятное):** Меняем `video_id` или `user_id` в запросе → получаем доступ к приватным данным.
2. **Гонка при авторизации:** Отправляем несколько параллельных запросов на логин → сессия создается для чужого аккаунта (или обход rate-limit).
3. **Утечка аналитики:** В запросах к `/api/v1/stats` или `/api/v1/analytics` меняем `channel_id` → получаем данные другого автора.
4. **XSS в комментариях:** Вставляем payload → он срабатывает в админке модератора.
