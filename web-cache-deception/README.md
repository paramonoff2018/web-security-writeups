# Web Cache Deception

Обман веб-кэша: заставляем кэш сохранить чувствительный динамический ответ, который затем может забрать атакующий.

## Лабы PortSwigger

- [Lab 01: Exploiting path mapping for web cache deception](./lab-01-path-mapping.md) ✅

## Прогресс: 1/13

## Ключевые концепции

- Атака работает из-за **расхождения** в парсинге URL между origin-сервером и кэшем.
- Origin может игнорировать лишние сегменты пути, а кэш — кэшировать ответ по расширению (`.js`, `.css`, `.ico`).
- Признаки кэша в ответе: `X-Cache: miss/hit`, `Cache-Control: max-age`, `Age`.
- Кэш-бастер (уникальный query string) нужен, чтобы при тестировании не получать закэшированные ответы.
- Защита: не переопределять `Cache-Control` от origin (`no-store`/`private`), не считать расширение файла признаком статики.
