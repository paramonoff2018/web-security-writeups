# Lab: Detecting NoSQL injection

**Тема:** NoSQL Injection (MongoDB)
**Платформа:** PortSwigger Web Security Academy
**Уровень:** Apprentice
**Дата:** 08.11.2026

## Цель
Обойти фильтр категорий товаров и вывести неопубликованные (скрытые) товары, используя синтаксическую NoSQL-инъекцию.

## Разведка и подтверждение уязвимости
1. В запросе фильтра GET /filter?category=Gifts добавлен апостроф ('). Сервер вернул ошибку синтаксиса JavaScript (500). Это подтвердило, что ввод попадает в код без экранирования.
2. Проверка логических условий:
   - Gifts' && 0 && 'x -> товары не выводятся (Ложь).
   - Gifts' && 1 && 'x -> товары выводятся (Истина).
   Это доказало, что мы можем внедрять свою логику в запрос к базе.

## Эксплуатация
3. Использован оператор || (ИЛИ) для создания всегда истинного условия:
   - Payload: Gifts'||1||'
   - Запрос URL-кодируется (Ctrl+U) и отправляется.
   - Сервер возвращает все товары, включая скрытые. Лаборатория решена.

## Корневая причина
Пользовательский ввод конкатенируется в запрос к MongoDB без проверки типа. Если вместо строки передать объект (или логический оператор через синтаксис), база данных воспринимает это как команду изменения логики запроса.

## Импакт (в реальном мире)
- **Information Disclosure:** доступ к скрытым данным (черновики, unpublished).
- **Authentication Bypass:** вход без пароля через password[\]=1.
- **Data Extraction:** Blind-инъекции для вытягивания базы данных.

## Рекомендации
- Использовать ORM (Mongoose) с параметризованными запросами.
- Валидировать типы данных (если ожидается строка, отклонять массивы и объекты).
- Санитизировать спецсимволы ($, {, }, ') на уровне middleware.
