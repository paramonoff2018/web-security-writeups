# DoS-safe PoC — PT AF Cloud

## Что ищем
Сценарии массового рестарта или деградации agents/borders **без проведения реальной DoS-атаки**.

## ⚠️ Это очень узкая и опасная категория
PT прямо пишет:
> Сценарии массового рестарта или деградации agents/borders без проведения реальной DoS-атаки.

То есть: **можно** показать уязвимость, которая *приведёт* к DoS, но **нельзя** проводить реальный DoS. PoC должен быть **безопасным** и воспроизводимым **в тестовом контуре**.

## Что ищем
- **Массовый рестарт:**
  - Команда / API, которая рестартит N agents/borders
  - Отсутствие rate limit / авторизации на рестарт
  - IDOR в API рестарта (чужой tenant)
- **Деградация:**
  - Утечка ресурсов (memory, file descriptors, connections)
  - Зависание при определённом запросе
  - Некорректная обработка большого payload'а (но без реального flooding)
- **Отказ в обслуживании:**
  - Перевод защищаемого ресурса в состояние «без фактической защиты»
  - Отключение inspection при определённом условии

## ⚠️ Ограничения PT (критично!)
- **Никаких реальных DoS-атак**
- **Никаких stress/load testing**
- **Никаких mass restart** (только PoC на 1–2 агентах в тестовом тенанте)
- **Никаких destructive payload'ов**
- **Только безопасный PoC в тестовом контуре**

## Как валидировать
1. **Воспроизвести в тестовом тенанте** (1–2 агента, не N).
2. **Показать причину:** конкретный запрос / API / конфиг.
3. **Показать эффект:** рестарт / деградация / отключение inspection — **на тестовом агенте**.
4. **Не навредить:** нет реального DoS, нет flooding, нет mass restart.
5. **Скриншоты:** состояние до / после, логи агента, консоль AF.

## Инструменты
- `curl` (точечные запросы)
- Burp (ручной)
- Логи агента (если доступны)
- `docker` / `kubectl` (для тестового тенанта)
