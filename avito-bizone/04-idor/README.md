# IDOR — Avito

## Что ищем
Insecure Direct Object Reference — доступ к объектам по ID без проверки владельца.

## Где искать
- Объявления (item_id, listing_id, ad_id)
- Чаты / сообщения (chat_id, message_id, thread_id)
- Платежи / заказы (payments.avito.ru) — order_id, transaction_id
- Профили (user_id, seller_id, account_uuid)
- Медиа (photo_id, video_id, image_uuid)
- Внутренние объекты (hrbt.ru, autoteka.ru) — отчёты, VIN-проверки
- GraphQL / gRPC — ID в аргументах запроса

## Типы ID
- Инкрементальные (item_id=123456)
- UUID (менее очевидно, но бывает предсказуемым)
- Base64/hex от внутреннего ID
- Slug / username

## Out-of-scope
- Перебор ID объявлений и пользователей (то есть «я нашёл, что /items/1, /items/2 работают» — не находка)
- Public-поля, которые и так видны

## Инструменты
- Burp Intruder (но без массового перебора — только PoC на 2-3 значения)
- Autorize
- Postman

## Чек-лист
- [ ] Создать объекты под аккаунтом A (объявление, чат, платёж)
- [ ] Запросить их под аккаунтом B → должен быть 403/404, а не 200
- [ ] Проверить ID в query, body, headers, cookies, GraphQL-переменных
- [ ] Проверить числовые ID на предсказуемость (только PoC!)
- [ ] Проверить, не утекают ли чужие объекты через вложенные эндпоинты (например, /chats/{id}/messages)

## Не делать
- Не перебирать диапазоны ID
- Не читать/не менять чужие данные за пределами PoC
- В отчёте — только 1–2 подтверждающих примера, без массивов
