# Lab: SQL injection vulnerability allowing login bypass

**Тема:** SQL Injection
**Платформа:** PortSwigger Web Security Academy
**Уровень:** Apprentice
**Дата:** 08.11.2026

## Цель
Обойти форму авторизации и войти в систему под пользователем dministrator без знания пароля.

## Разведка и эксплуатация
1. Перехвачен запрос POST /login с параметрами username и password.
2. Параметр username изменен на полезную нагрузку: dministrator'--.
3. Запрос отправлен в Repeater. Сервер вернул 302 Found и заголовок Location: /my-account?id=administrator.
4. Для активации сессии использована функция **Show response in browser** в Burp Repeater (передача Cookie). Лаборатория решена.

## Корневая причина
Пользовательский ввод конкатенируется в SQL-запрос без параметризации. Символы -- воспринимаются базой данных как начало комментария, что позволяет отсечь часть запроса с проверкой пароля.

## Импакт
Полный обход аутентификации (Authentication Bypass). Злоумышленник получает доступ к аккаунту администратора и может выполнять любые действия от его имени.

## Рекомендации
- Использовать параметризованные запросы (Prepared Statements).
- Применять ORM с автоматическим экранированием.
- Валидировать входные данные (запрещать спецсимволы SQL, если они не ожидаются).
